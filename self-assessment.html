Patrick Harrington CS 499 Computer Science Capstone

Completing the Computer Science program and developing my CS 499 ePortfolio have given me an opportunity to bring together the technical, analytical, communication, and professional skills developed throughout my coursework. The program has strengthened my ability to approach computing problems systematically, evaluate alternative solutions, communicate technical information to different audiences, and consider security and maintainability as essential parts of software development. The capstone has been especially valuable because it requires more than demonstrating that an application works. It requires me to examine earlier work critically, identify areas for improvement, implement meaningful enhancements, document the reasoning behind those decisions, and present the results as a cohesive professional portfolio.

This process has also helped shape my professional goals and values. I want my work to demonstrate reliability, clarity, continuous improvement, and responsible use of technology. Rather than treating programming as only the production of source code, I now view professional computer science work as a combination of problem solving, design, testing, data management, security, documentation, and communication. Building the ePortfolio has made those connections visible and has provided concrete evidence of skills that I can discuss with employers.

Program Growth and Professional Preparation

Coursework throughout the program developed complementary skills that support my preparation for the computer science field. Programming coursework strengthened my ability to create functional programs while considering efficiency, readability, secure practices, and professional standards. Discrete Mathematics strengthened the logical foundation behind computing through topics such as sets, logic, relations, functions, trees, counting, and graph theory. These experiences are useful beyond any single application because they reinforce structured reasoning and the ability to represent and solve problems precisely.

The capstone extends that foundation by requiring me to revisit a previous project and improve it across multiple areas of computer science. This is closer to professional development than simply starting a new classroom project because existing behavior must be understood and preserved while weaknesses are identified and corrected. The process has required planning, versioned publication through GitHub and GitHub Pages, written narratives, visual evidence, and a code review. It has also required me to respond to instructor feedback and improve the way technical work is presented. These activities have strengthened both my technical competence and my ability to present that competence professionally.

Collaboration and Communication

Effective computer science work depends on collaboration even when an individual is responsible for implementing a particular component. Throughout the program, I have learned that productive collaboration requires clear requirements, shared terminology, organized documentation, and an awareness that people may approach the same problem from different perspectives. A collaborative environment is strongest when technical decisions can be explained in a way that allows teammates and stakeholders to evaluate trade-offs and contribute to decisions.

CS 499 has reinforced this principle through the requirement to communicate the same technical work in several forms. The code review requires oral and visual communication, the enhancement narratives require professional written communication, and the GitHub Pages portfolio requires information architecture and navigation that make the work understandable to a reviewer. Instructor feedback has also demonstrated the importance of adapting communication to an audience. For example, feedback on the enhancement milestones recommended adding supporting screenshots of code changes so that readers could see evidence of the work instead of relying only on a text description. Incorporating representative code-change images into the portfolio makes the technical improvements easier to verify and strengthens the connection between explanation and implementation.

This experience supports my ability to communicate with stakeholders because a stakeholder does not always need the same level of detail as a developer. A technical peer may need implementation details, while a manager or end user may need to understand the purpose, reliability, risks, and value of a change. Learning to adjust the depth and format of communication while keeping it technically accurate is an important professional skill.

Data Structures and Algorithms

My coursework has developed my understanding that algorithms and data structures determine not only whether a solution works, but also how clearly, efficiently, and predictably it works. Mathematical and programming concepts from the program provided a foundation for evaluating logical relationships, organizing data, and considering algorithmic trade-offs. In CS 499, these principles became a central part of the Algorithms and Data Structures enhancement.

The original rescue-filter workflow in the selected project used static filtering to identify qualifying animal records. The enhanced design introduces structured rescue profiles, dynamic query construction, weighted candidate scoring, stable ordering, and bounded result selection. Candidate records can be evaluated according to relevant criteria rather than treating every qualifying record as equally suitable. The use of a bounded ranking approach also demonstrates attention to complexity and result size. Just as important, the ranking is explainable: the application can associate human-readable reasons with scoring decisions rather than producing an opaque result.

This work demonstrates growth in designing and evaluating computing solutions using algorithmic principles while considering trade-offs. More sophisticated ranking adds complexity compared with a simple Boolean filter, but it also produces more useful and predictable decision support. Unit tests for query construction, fallback behavior, defensive copies, scoring, ranking order, bounded results, and reset behavior provide additional evidence that the algorithmic design is deliberate and verifiable.

Software Engineering and Databases

Software engineering coursework taught me that maintainability and quality depend on architecture as much as on individual functions. The CS 499 Software Design and Engineering enhancement applies this principle by moving the Grazioso Salvare dashboard from a largely notebook-centered implementation toward a more modular Python application. Responsibilities are separated into focused areas for configuration, logging, rescue filters, data access, and application behavior. Dependency management, validation, targeted exception handling, documentation, type hints, and automated tests make the application easier to understand and maintain.

Database work is equally important because applications depend on accurate, secure, and efficiently accessible data. The selected project uses MongoDB through an AnimalShelter data-access class that supplies create, read, update, and delete operations for shelter records. Working with a client/server application has reinforced the importance of keeping user-interface concerns separate from database operations, validating data and queries, handling database failures predictably, and designing access patterns that support application requirements. The database enhancement in the capstone builds on these principles by focusing on stronger validation, safer CRUD operations, indexing and query considerations, aggregation, timestamps, and database health reporting.

Together, software engineering and database skills demonstrate my ability to work across application layers rather than treating the user interface, business logic, and persistence layer as unrelated pieces. This broader view is important for professional development because changes in one layer can affect reliability, performance, security, and usability elsewhere in the system.

Security Mindset

Security has become a design consideration rather than an activity that should be postponed until an application is complete. The original project included hardcoded credentials and limited defensive programming, which provided clear opportunities for improvement. In the enhanced application, credentials are removed from source code and configuration is read from environment variables. Required values and port ranges are validated, credential values are safely encoded for the connection URI, and placeholder configuration documentation supports safer setup.

The enhancements also improve defensive behavior around data access. CRUD inputs are validated, unsafe empty update or delete queries are rejected, read limits are checked, and targeted exception handling and centralized logging replace broad error handling and simple print statements. These changes demonstrate a security mindset because they anticipate misuse, invalid states, accidental destructive operations, and unnecessary exposure of sensitive information. Security therefore becomes part of architecture, validation, error handling, and data management rather than a separate feature.

Course Outcomes and Professional Strengths

The work completed throughout the program and in CS 499 provides evidence across the capstone course outcomes. Collaborative and stakeholder-focused practices are demonstrated through organized documentation, audience-aware communication, and the presentation of information that supports decision making. Professional-quality communication is demonstrated through the code review, written narratives, screenshots, technical documentation, and navigable ePortfolio. Algorithmic problem solving is demonstrated through the design and evaluation of filtering, scoring, ranking, and data-processing approaches while considering trade-offs. The use of Python, Dash, Plotly, Pandas, MongoDB, testing, GitHub, and GitHub Pages demonstrates the application of established tools and techniques to create solutions with practical value. Finally, configuration protection, validation, safer database operations, logging, and defensive programming demonstrate a security mindset that anticipates vulnerabilities and protects data and resources.

The combination of these areas is one of the strongest results of my program experience. My preparation is not limited to writing code in a single language or completing an isolated algorithm. I can examine requirements, structure an application, work with persistent data, evaluate algorithmic choices, test behavior, consider security, document decisions, and communicate the result to an audience. Those connected abilities are the professional strengths I intend to continue developing as I enter the computer science field.

Portfolio Introduction and Artifact Integration

The ePortfolio that follows provides tangible evidence of this progression. Its central artifact is the Grazioso Salvare animal-shelter dashboard originally created for CS-340 Client/Server Development. The project combines a Python application with MongoDB data access, interactive filtering, tabular information, visualizations, and map-based location information. Using the same artifact across the three enhancement categories makes the portfolio a cohesive record of growth because each stage improves a different dimension of the same working system.

The Software Design and Engineering enhancement demonstrates modular architecture, secure configuration, validation, structured logging, targeted exception handling, documentation, and testing. The Algorithms and Data Structures enhancement adds structured rescue profiles, dynamic query construction, weighted candidate scoring, stable ranking, bounded result selection, and algorithm-focused tests. The Database enhancement extends the project through stronger data validation, safer database operations, indexing and query improvements, aggregation, audit-friendly data, and database health considerations. The original and enhanced versions, supporting narratives, screenshots, and code review allow a reviewer to compare where the project began with how it developed throughout the capstone.

As a whole, the portfolio represents more than three separate assignments. It demonstrates an integrated approach to computer science in which software architecture, algorithms, databases, security, testing, and communication support one another. The progression from the original classroom artifact to the enhanced application illustrates my ability to evaluate existing work, make justified technical improvements, incorporate feedback, and communicate the resulting value professionally. This self-assessment serves as the introduction to that evidence and summarizes the knowledge, skills, and professional perspective I will carry forward from the Computer Science program.
